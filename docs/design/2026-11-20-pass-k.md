# pass^k: how stable the agent's answers are across runs

**Status:** approved 2026-11-20 (user: build the tool, measure `smoke` 30 questions with k=3).
**ADR:** [0040](../adr/0040-pass-k.md).

## Why

Groq results vary run to run, so a change of a few points cannot be told from noise. pass^k runs
each question k times and reports how many are right every time (pass^k, the tau-bench metric),
right at least once (pass@k), and the spread of the total score: the noise floor a change must beat.
Questions that are right only sometimes point at ambiguous prompts or rules.

## Goals and non-goals

- `uv run python -m eval.datamate.passk --k 3 --data-dir ... --set smoke -- <run.py options>` runs
  the eval k times into `OUTPUT/run-1..k`, scores each in a separate process (the agent process
  never loads answers), and writes `OUTPUT/passk.json`.
- A stopped pass^k run continues: each `run.py` resumes its own folder.
- vLLM runs get seed `--seed-base + i` (`VLLM_SEED`), since a fixed seed gives k identical runs.
- Non-goals: confidence intervals beyond mean and standard deviation; comparing two pass^k runs
  (later); running on the worker.
- Anti-goals: per-question data in committed files (the report stays in gitignored `eval/reports/`;
  only aggregates go to `docs/eval/`).

## Approaches

| Option | Trade-off | Decision |
|---|---|---|
| A. Separate `passk.py` that calls `run.py` k times | Reuses run, resume, record; one folder per run | **Chosen** (Claude's call; user handed over the how) |
| B. `--repeat k` inside `run.py` | One process, but `run.py` already mixes many concerns, and resume per repeat is harder | Rejected |

## Design

- Per run: `run-i/score_details.json` from `eval.scorer.cli --details`.
- `passk.json`: `k`, `seeds`, per-run `{score, correct, wrong, abstained}`, `score_mean`,
  `score_std` (sample), `score_min`, `score_max`, `questions`, `pass_hat_k` (right in all k),
  `pass_at_k` (right in at least one), `mean_accuracy`, `always_wrong`, `always_abstain`, and
  `flaky`: ids right in some runs and not others, with their outcome per run.
- Extra `run.py` options pass through after `--`, for example `--record` (k cassettes, so any run
  can be replayed later) or `--workers`.
